## Prompt

```
Implement US-04 from REQUIREMENT.md: show the videos generated by tooling/videoGrabber.
1. On startup (AppStartupRunner), when pro_tube.load_initial_data=true, import every <id>.json in

   id, width, height, duration, title, user, timestamp, meta{description, categories, tags, view_count,
   like_count, channel, channel_follower_count, comments}. Create a placeholder author per user/channel and
   import the comments too.
2. GET /api/videos?page=&size= returns a page of VideoSummaryDto (id, title, author, duration, views,
   thumbnail path). Replace the placeholder VideoService.getVideos().
3. Frontend home: responsive Bootstrap grid of cards (thumbnail <MEDIA_BASE_URL>/<id>.webp, title, author,
   duration), pagination or infinite scroll, loading/error/empty states. Remove the template samples
   (useAllVideos, VideoGrid) once replaced.
4. Tests: importer with a @TempDir store, service, controller (MockMvc) and the frontend list.
```

## Notes

* Tool / model: Claude Code, Claude Opus 5.5.
* Schema changes go in a new Flyway migration (`V2__video_store_import.sql`): `videos.store_id` (unique, used
  for idempotency), `view_count`, `like_count`, and `video_categories` / `video_tags` tables.
* Each JSON file is imported in its own transaction; unreadable files or files without `id`/`title` are logged
  and skipped. Placeholder users get a deterministic `<uuid>@placeholder.protube.local` email and an unusable
  password (`!`), so they cannot log in.
* The response uses a `PageDto` record instead of serialising Spring's `PageImpl` (not a stable JSON contract).
* Frontend uses infinite scroll (`IntersectionObserver`) with a "Load more" button as fallback.
* Jest needed a `moduleNameMapper` for `.css` imports once `App.tsx` became testable.
* Comment `like_count` from the JSON is not stored (likes are per-user rows in `comment_likes`).
* The `prod` profile keeps `pro_tube.load_initial_data=false`; Docker Compose overrides it with the
  `PRO_TUBE_LOAD_INITIAL_DATA` environment variable.
